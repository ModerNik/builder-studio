# Design System: Builder Studio

The source of truth for every value is `src/renderer/src/app/styles/main.css`; `src/renderer/src/app/styles/tokens.test.ts` pins the contrast pairs. The frontmatter lists the dark value of each key role and its `-light` twin; the prose names roles, not numbers.

## Overview

**Creative North Star: "The Deepslate Workbench"**

Builder Studio is a workbench cut from cool grey stone with one vein of weathered copper running through it. The chrome is deepslate: near-neutral greys with a barely-cool tilt (hue 265, chroma under 0.01), so a builder's block colours read true beside it. The only saturated colour the chrome owns is verdigris, the green-teal of oxidised copper, and it is spent on what the user can act on: the primary action, focus, selection and whatever is running right now. Everything else is the build.

The product is an Operate surface for long, iterative sessions (brief, draft, review, revise, export), often with an AI assistant at the side. So the system is dense and calm: 16px text, 36px controls and rows, short colour-only transitions, and depth told by stepped surface lightness rather than shadows. Dark is the default and primary theme; light is complete, not an afterthought; System follows the OS.

**Key Characteristics:**

- Neutral stone chrome that never tints the 3D view, previews or palettes; the viewer sits on a pure grey backdrop (chroma 0).
- One accent (verdigris, hue 175); semantic hues (success, warning, danger, info) only for status.
- Compact density on a mouse, 44px targets on touch, from the same tokens.
- Calm motion (M1): 120 / 180 / 240 ms, one ease-out, 4px travel, colour-only press.
- Every text pair meets WCAG 2.2 AA in both themes, enforced by a test.

## Colors

A deepslate neutral family carries the interface; verdigris marks the actionable and the live; status hues appear only where status is.

### Primary

- **Verdigris** (`accent-solid`; light `accent-solid-light`): primary buttons, the focus ring, the selected-tab indicator, the running state and the open review pin. Hover lifts lightness (`accent-solid-hover`), press drops it (`accent-solid-active`). Text on it uses `accent-on-solid` (dark ink in dark theme, white in light).
- **Verdigris Text** (`accent-text`): links and accent text on any surface. In light theme never set body text in `accent-solid`; use this.
- **Patina Tint** (`accent-subtle-bg`, border `accent-subtle-border`): selected rows, the running chip, "assistant is working" callouts.
- **Selection** (`selection-bg`): text selection and multi-select highlight; `fg` stays readable on it.

### Neutral

- **Sunken** (`surface-sunken`): input wells, code blocks, the area under docks.
- **Deepslate** (`surface-bg`): the app background and the title bar; the window's title-bar overlay uses this exact colour.
- **Panel** (`surface-panel`): sidebars, docks (Editor, Assistant, Activity), the settings rail.
- **Raised** (`surface-raised`): cards, settings panels, gallery tiles.
- **Overlay** (`surface-overlay`): menus, popovers, dialogs, toasts and, at 92% opacity, the glass over the 3D view.
- **Hover / Active** (`surface-hover`, `surface-active`): state fills only, never resting backgrounds.
- **Viewer Grey** (`surface-viewer`): the 3D view, preview and map backdrop. Pure grey (chroma 0) so blocks read true.
- **Scrim and Inverse** (`surface-scrim`; `surface-inverse` with `fg-inverse`): modal scrim; tooltips and the selected pin.
- **Text tiers:** `fg` (primary text and icons), `fg-secondary` (labels, secondary values), `fg-muted` (hints, meta, placeholders), `fg-disabled` (disabled only; exempt from contrast).
- **Borders:** `border-subtle` (dividers inside a panel), `border-default` (panel and card edges; the kit's `border`), `border-strong` (input and control outlines; meets 3:1). Separators inside menus, context menus, selects and the command list are `border-strong` at 40%: `border-subtle` is darker than `surface-overlay` in dark and disappears there.
- **Deepslate ramp** (`--deepslate-0` to `--deepslate-975`, Tailwind `deepslate-*`): the absolute neutral ladder the roles pick from. UI code uses roles; the ramp is for illustration and charts.

### Semantic

Each of **success** (hue 148), **warning** (80), **danger** (27), **info** (255) and **neutral** has `-solid`, `-solid-hover`, `-on-solid`, `-subtle-bg` (Tailwind `-subtle`), `-subtle-border` and `-text`. Solid for badges and destructive buttons; subtle background, border and text for callouts and chips; text alone for inline status. The kit's `destructive` maps to `danger-solid`; the older `ok` and `warn` map to `success-text` and `warning-text`.

### Domain sets

- **Job and agent states:** `state-{idle, queued, running, awaiting-approval, done, failed, cancelled}-fg` on `-bg` (Tailwind `state-running`, `state-running-bg`). Running is verdigris, awaiting approval is warning, done is success, failed is danger; idle, queued and cancelled are neutral. Always paired with an icon or word.
- **Diff:** `diff-{added, removed, changed}-fg` (text; Tailwind `text-diff-added`), `-bg` (row tint), `-mark` (3D legend, gutter). Hues 128 / 25 / 95 echo the lime, red and yellow stained glass the engine draws in 3D.
- **Lint:** `lint-error`, `lint-warning`, `lint-info`, `lint-hint` alias danger, warning and info text and `fg-secondary`.
- **Axis:** `axis-x` red, `axis-y` green, `axis-z` blue; 4.5:1 on the viewer grey and on panels.
- **Review pins:** `pin-{open, selected, resolved}` fill, `-text` and `-ring`. Open is verdigris, selected is inverse, resolved is neutral.
- **Categorical:** `cat-1` to `cat-8` in fixed order (blue, orange, teal, amber, pink, green, violet, red) for check overlays and charts; `chart-1` to `chart-5` alias the first five.

### Named Rules

**The Verdigris Budget Rule.** The accent marks what the user can do next or what is running now. A screen at rest shows it on at most one primary action, plus focus and live state.

**The True Block Rule.** Chrome never tints the build: the viewer backdrop is chroma 0, overlays on it are neutral glass, and no accent wash sits behind previews.

**The Status Is Not Decoration Rule.** Semantic and state colours appear only where that status is true, always with an icon or label.

## Typography

**UI Font:** Hanken Grotesk (variable, bundled with `@fontsource-variable/hanken-grotesk`), falling back to the system UI font.
**Mono Font:** JetBrains Mono (variable, bundled) for code, paths, block ids, coordinates and shortcuts.

**Character:** Hanken Grotesk is a sturdy, slightly technical grotesque that stays crisp from 12px meta to 16px body; JetBrains Mono gives the exact things (paths, ids, numbers) a distinct, even voice.

### Hierarchy

The scale uses Tailwind's `text-*` names; each step carries its own line height, weight and tracking.

- **Display** (`text-3xl`, 600, 28→36px fluid): empty-state and onboarding headlines only.
- **Headline** (`text-2xl`, 600, 24→30px fluid): page titles (Gallery, Docs).
- **Title large** (`text-xl`, 600, 22→24px fluid): settings section headers, dialog titles.
- **Title** (`text-lg`, 600, 20/28): panel and card titles.
- **Emphasis** (`text-md`, 500, 18/26): row titles that need weight, shell tab labels.
- **Body** (`text-base`, 400, 16/24): the default for UI text, rows and controls (set on `body`).
- **Secondary** (`text-sm`, 400, 14/20): meta lines and helper text.
- **Label** (`text-xs`, 500, 13/18): field labels, column headers, chips.
- **Micro** (`text-2xs`, 500, 12/16): compact counters and badges only.
- **Mono** (`font-mono`, one step below the text around it): paths, ids, coordinates.

### Named Rules

**The Tabular Numbers Rule.** Every number that changes or lines up (counts, coordinates, sizes, timers, tables) uses `tabular-nums`; running prose keeps proportional figures.

**The Sixteen Rule.** UI text is 16px (`text-base`, 1rem, so OS and browser zoom scale it). `text-sm` (14px) is for secondary text; `text-xs`/`text-2xs` (13/12px) are for labels and meta only, never for something the user must read to act. Nothing is smaller than 12px. Font sizes are always scale classes, never pixel literals.

## Layout

A 4px spacing base (Tailwind's `p-1` is 4px; raw `--space-*` for plain CSS). Gaps inside a control are 4 to 8px, between related controls 8px, between groups 16px, between sections 24 to 32px.

**Window growth.** Off: the root size is a fixed 16px at every window width (`--root-size-max` is set to `--root-size-min` in `main.css`). Type, density, spacing, shell and container tokens are rem, so text, controls and panels still follow the root together; hairlines, radii, breakpoints and the 36px title bar stay px. Raising `--root-size-max` (it was `1.25rem`) turns growth back on along `--root-size-fluid`: 16px at a 1440px-wide window, plus 1px per 240px. Users also scale the whole UI with Ctrl − / Ctrl + / Ctrl 0 (67–200%, saved as `appearance.scale`). Pixel values below are at a 16px root.

**Density.** Compact on fine pointers: `--density-control` 36px, `--density-control-sm` 30px, `--density-row` 36px, `--density-icon-button` 36px, `--density-gap` 8px, `--density-text` 16px. Under `(pointer: coarse)` the same tokens become 44 / 40 / 48 / 44px, gap 12px, text 16px. Components size from these tokens, never from literals.

**Breakpoints** (px): xs 360, sm 640, md 768, lg 1024, xl 1280, 2xl 1536, 3xl 1920. Every screen works from 360px wide to 4K; panels adapt with container queries (the Workspace toolbar collapses at 1100px).

**Widths:** `max-w-prose` 68ch, `max-w-dialog` 480px, `max-w-dialog-lg` 720px, `max-w-settings` 880px, `max-w-page` 1280px, `max-w-wide` 1536px.

### The S3 Workbench shell

The chosen shell (built in a later phase) is a workbench: a title bar, document tabs, a central canvas and dockable side and bottom panels.

- **Title bar** (`--shell-titlebar` 36px): app mark, breadcrumbs, command palette, global actions. The OS window buttons draw over its right end in `surface-bg` with `fg` symbols, updated live when the theme changes.
- **Document tabs** (`--shell-tabbar` 40px): one tab per open build or tool page.
- **Canvas:** the 3D view, preview, compare or page body. Docks never cover it on wide windows.
- **Docks:** Editor (right, `--dock-editor` 300px), Assistant (right, `--dock-assistant` 372px), Review rail (right, `--dock-review` 360px, room for the question field and the pin rows), Activity (bottom, `--dock-activity` 220px). Resizable up to `--dock-max` (560px at default density), with panel-specific minimums. On narrow windows docks become sheets. Docks sit at `z-dock`. Opening, closing or resizing a dock, or crossing a width tier, never reloads the screen: its 3D view and state stay as they were. Docks have no tab strip and no header: the Panels toggles beside the screen tabs (right docks in left-to-right order — Editor, Review or Inspector, then Chat — followed by bottom docks such as Activity) and their shortcuts show and hide them. Where two right panels share one column (desktop tier), the one toggled last is in front and the other stays mounted behind it; toggling the front one closes it. On narrow windows the sheet shows the one panel its toggle asked for, under that panel's title, with Full height and Close.
- **App pages** (Gallery, Settings, Documentation, Labs): the same title bar with no document-tabs row and no docks (`WorkbenchShell` with no screens and no panels; kit › Workbench, App page). The Assistant dock (Ctrl+J) lives inside a build and is configurable per build tab. **Setup** uses a title bar with the Setup crumb and no search over the wizard.

## Elevation & Depth

Depth is tonal first: in dark, higher surfaces are lighter (sunken, bg, panel, raised, overlay); in light, panels turn white over a grey background. Flat panels use a border only. Floating layers (menus, popovers, dialogs, toasts, the viewer glass) add a shadow plus a 1px `border-subtle` or `border-default` ring.

### Shadow Vocabulary

Tailwind `shadow-sm` to `shadow-xl` map to `--elevation-*`, which differ per theme (deep black in dark, soft slate in light).

- **sm:** sticky headers, pressed-in controls.
- **md:** menus, popovers, toasts, the viewer glass (`--shadow-overlay`).
- **lg:** dialogs and sheets.
- **xl:** the command palette.

### Layers

`z-sticky` 10, `z-dock` 20, `z-floating` 30 (viewer overlays), `z-overlay` 1000 (scrims), `z-modal` 1100, `z-dropdown` 1200, `z-popover` 1300, `z-toast` 1400, `z-tooltip` 1500. Menus and selects sit above modals because they open from controls inside dialogs.

**The Flat At Rest Rule.** A panel that does not float has no shadow.

## Shapes

Gently squared corners: `rounded-md` (6px) for controls, inputs, buttons and chips; `rounded-lg` (10px) for panels, cards, menus and dialogs; `rounded-xl` (14px) for touch sheets; `rounded-full` only for status dots, the status chip and switches. Borders are 1px hairlines; `--border-strong-width` (1.5px) for selected outlines; the focus ring is `--focus-width` 2px at `--focus-offset` 2px.

## Motion

M1 Calm. Durations: `duration-fast` 120ms (hover, press, colour), `duration-base` 180ms (open and close, tabs, collapse), `duration-slow` 240ms (docks, sheets, progress). Easing: `ease-standard` and `ease-enter` are cubic-bezier(0.2, 0.7, 0.2, 1); `ease-exit` is cubic-bezier(0.4, 0, 1, 1) at about three quarters of the enter duration. Travel is 4px (`--travel`); popovers grow from scale 0.98.

- Press is colour-only. The one exception is the primary button, which scales to `--press-scale-primary` (0.97).
- Spinners, shimmer and the working dot mean work is happening; nothing animates at rest.
- **Reduced motion:** under `prefers-reduced-motion: reduce`, fast becomes 0ms, base and slow 120ms, travel 0 and the press scale 1. Shimmer and sweeps stop and show a static state with text.

### Workbench usability

- **Editor tabs.** The Editor dock (it was the Inspector) uses the line tab treatment in four equal columns: Edit, Parts, Checks and Materials, with labels when all four fit and the matching icons below that width. Each icon keeps its accessible name and tooltip. The tab strip is the dock's only header. The Editor dock stops at 21rem, the Chat dock at 22rem, and a shared dock uses the larger minimum. Narrow workbenches use the existing panel sheet. A drag or keyboard resize updates the canvas live and saves the final width.
- **Workbench actions.** Build tabs have one Chat button with a speech-bubble icon (where enabled for that tab), one Editor (or Review/Inspector) button where available, and an Activity button on Workspace (with a live running or failed dot); they are the only way docks open and close (no dock tab strip). The Chat button carries the "needs you" count. App pages have no Chat toggle or dock. The right rail is removed. Global actions are grouped before a hairline at the native caption edge. The Search trigger is centered in the full window and reduces to a labeled icon where the field would collide with either side. Native caption colors follow the resolved app theme.
- **Composer.** Keep the paperclip, permission mode, combined Model and Effort menu, and Send or Stop on one row. Active plans (`ExitPlanMode` or the newest Codex plan item) show a `Rev n` badge (`tabular-nums`) once revised, a `Diff` toggle comparing against the previous plan revision (`DiffView`), and an `Edit` toggle switching the body to a markdown `Textarea` with `Done` and `Reset edits` (`Approve edited plan` sends the edited text). Selecting text inside the rendered plan reveals a floating `surface-overlay` `shadow-md` `Comment` button anchored above the selection; clicking opens an inline comment box with the quoted excerpt. Saved comments list below the plan with quoted excerpts and remove buttons, and an inline revision input (`Tell the assistant what to change…`) sends all comments and notes as revision feedback (`Send n comments` / `Revise`). Superseded historical plans render read-only with their revision badge and optional diff toggle.
- **User message quick actions and inline edit** (`MessageBubble`; kit › Transcript items). Right-aligned beneath each user bubble sits a quiet `xs` action bar (`Copy`, `Edit`, `Fork`, `Rewind`) using `CopyButton` and `IconAction` (`Pencil`, `GitFork`, `RotateCcw`): hidden at rest on fine pointers (`opacity-0`, fading in over `--dur-fast` on hover and `focus-within`) and always visible on coarse pointers. `Copy` stays enabled at all times; `Edit`, `Fork` and `Rewind` disable while a turn is running. Clicking `Fork` branches a new thread through that turn's reply; clicking `Rewind` opens `RewindDialog` pre-selected to that turn; clicking `Edit` replaces the bubble with a `surface-raised` (`border-default`, radius lg) inline editor holding an auto-focused `Textarea`, preserved attachment chips, an opt-in build-file undo `Checkbox` showing the affected files whenever checkpoints exist (`Undo changes to n build files`), `Cancel` (`Esc`), and `Resend` (`Ctrl+Enter`, switching to destructive `Resend & undo files` when file undo is checked).
- **Chip and lane tooltips** (`AttachmentChip`, `ContextChip`, `LaneSwitcher`). The full path, the context sent and the lane's brief show in the kit Tooltip, not a native `title`. Each trigger takes keyboard focus (with the focus ring) and carries the same text for screen readers: an `aria-label` on a named group or the lane button's own label.
- **Transcript** (`Transcript` in `chat/Transcript`; kit › Transcript items). A conversation's items composed from the chat parts: message bubbles, notes, assistant prose, tool rows (an Edit or Write opens its diff), build.py runs as job cards and subagents as cards with their steps nested. Open asks come last, right above the composer: ExitPlanMode as a PlanCard, structured questions as a QuestionCard, anything else as a PermissionCard with its diff or command; then the working line with its timer, then the screen's own children (an error Alert). A `role="log"` scroll area that sticks to the bottom unless the reader scrolled more than 80px up; the column is capped at 68ch and centred. It never scrolls sideways: long ids, paths and tool names wrap anywhere, the log hides x overflow, and the Agent panel clips its own, so the dock never gets a horizontal scrollbar. Header titles truncate instead of widening their row. It takes callbacks, not IPC, so the Agent panel and each Variants lane bind it to their own thread.
- **Palette strip** (`PaletteStrip`, `PaletteTile`; kit › Palette strip). Block tiles in a wrapping row on `surface-viewer`, radius lg, 8px padding, 4px gaps, so block colours read the same in both themes. A tile is a button at sm 72 / md 96 / lg 120px: the square swatch with a 1px `border-strong` inner ring (a dashed `fg-muted` outline when the block has no texture), the id in 12px mono breaking at underscores, then L to two places (12px mono, tabular; dropped at sm). Hover and selected (`aria-pressed`) take `surface-overlay`; selected adds an `accent-solid` border. Click copies the id (`useCopy`, Copied badge for 1.5s). Its name is "id, L 0.47, click to copy". **Shade check** (`check`, ramps): under each tile a 40px bar to its lightness and the step from the tile before; a step under 0.04 (reads as one shade) or over 0.20 (a jump) turns the bar `warning-solid` and the number `warning-text`, and says why to screen readers. The check line under the strip (14px `fg-secondary`) comes from the screen.

  ### Parts selection and generation
  - Parts selection is automatic: a 15% accent-colour fill and a thin visible silhouette, without glow or hidden edges. Block textures remain readable. Clearing selection removes the mask; Isolate keeps the selected geometry and its mask.
  - The Parts toolbar contains Colour by, Isolate, the selection count and Clear. There is no Highlight toggle.
  - Generation uses a compact neutral viewer overlay in the existing toolbar status position: a plain stage label and the shared Progress bar. Percentages describe the current measurable stage, not an estimated overall duration. Reading, saving and waiting are indeterminate. It remains visible until the replacement mesh is ready.
  - Progress has an accessible name and polite stage announcements; reduced motion follows the shared Progress component. Changes do not block camera or selection controls.

### Working with the kit

Every screen is built from this design system and the UI kit, and everyone who works on the repo keeps both up to date.

- **Design system:** this file holds the rules, tokens and component list. The tokens themselves live in `src/renderer/src/app/styles/main.css`, in both themes.
- **UI kit:** the domain-free components in `src/renderer/src/shared/ui/` (`primitives/` and the family folders `feedback/`, `layout/`, `data/`, `code/`, `status/`, `common/`) and the presentational components in a slice's `ui/` folder. The `/kit` route (**Settings → Advanced → UI kit**) shows every component in every state, both themes and both densities. It exists only in development (`npm run dev`): production builds leave out the route, the settings row and the catalogue code. Each entry is one file in `src/renderer/src/pages/kit/sections/` that exports `meta = { group, title }` and a default component; the catalogue picks new files up by itself.

When a screen needs a component, variant or state the kit does not have, work in this order:

1. **Design it** against this file: tokens only, density sizes, both themes, every state (default, hover, active, focus-visible, disabled, loading, invalid, selected, open and closed), coarse-pointer size, motion tokens with reduced motion, semantics and keyboard use. Add it to the inventory above. A new token goes into `main.css` for both themes and must pass `tokens.test.ts`.
2. **Add it to the kit:** the component under `src/renderer/src/shared/ui/` (or the `ui/` folder of the slice that owns it), with no Electron or IPC imports, and a section in `pages/kit/sections/` that shows every state.
3. **Implement it** in the screen. Screens in `pages/` compose kit components and do not style one-offs.

Changing an existing component or token follows the same order, and this file, the component and its kit section change together in one commit. UI work without its kit section and its entry here is not finished.

ESLint checks part of this: above `shared/` it warns on native `<select>`, `title=` on buttons and hex colors, and it warns on pixel font sizes everywhere.

### Renderer layout

`src/renderer/src/` follows Feature-Sliced Design. A layer imports only from the layers below it, and ESLint enforces that (`no-restricted-imports` in `eslint.config.mjs`).

| Layer       | Holds                                                                                                                                                                 |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app/`      | The root layout (`ui/Shell`), setup gate, crash screen and global styles (`styles/main.css`). `main.tsx` holds the route table.                                       |
| `pages/`    | One slice per route: `gallery`, `workspace`, `review`, `design-log`, `ship`, `site`, `refs`, `variants`, `labs`, `docs`, `settings`, `setup`, and the dev-only `kit`. |
| `widgets/`  | Large self-contained blocks: `workbench-shell`, `version-compare`, and `block-editor` (the Editor's hook, tool rail, tool HUD and Edit tab, which runs the tools).    |
| `features/` | User actions that span pages: `agent-chat`, `import-schematic`, `import-projects`, and the `block-tools` group with one slice per Editor tool (below).                |
| `entities/` | Domain objects: `block`, `block-edit`, `build`, `job`, `settings`, `availability`, `parts`, `ref`, `review`, `site`, `update`, `viewer`.                              |
| `shared/`   | `ui/` (the kit), `api/` (the IPC client) and `lib/` (domain-free helpers).                                                                                            |

Inside a slice, `ui/` holds components and their CSS and `model/` holds stores, hooks and pure logic with their tests. Imports inside a slice are relative; imports between slices use the `@/` alias.

The Editor's tools follow the same layers:

- `entities/block-edit` holds what every tool shares: the tool ids, reading a cell against the build, changes, the size limits, cell geometry, the hand-edit layer with its history and store, and the option rows each tool's settings are made of (`ui/OptionRows`).
- `features/block-tools/<tool>` is one slice per tool (`brush`, `paint`, `fill`, `shape`, `terrain`, `transform`, `ruler`): its pure logic, options type and tests in `model/`, and its settings panel in `ui/`. A tool slice imports only from `entities` and `shared`, never another tool.
- `widgets/block-editor` puts them together: the tool registry (`model/tools`), all tools' options and the HUD summary (`model/options`), the stroke dispatch (`model/draw`), the `useBlockEditor` hook, and the rail, HUD, Edit tab and the switch that shows the active tool's panel.

A new tool gets its own slice under `features/block-tools/`, then an entry in the widget's registry, options, and `ToolOptions` switch.

A `ui/` file renders from props and model hooks. It may not import the IPC client (`@/shared/api/*`), `@tanstack/react-query` or a `zustand` store factory; type imports and `zustand/react/shallow` are fine. ESLint fails on it (`@typescript-eslint/no-restricted-imports`). IPC calls, queries, mutations, stores and `localStorage` access live in the slice's `model/` as `use<Thing>` hooks or plain functions.

## Do's and Don'ts

### Do:

- **Do** use role tokens (`bg-surface-raised`, `text-fg-muted`, `bg-success-subtle`, `text-diff-added`) or the kit names (`bg-card`, `text-muted-foreground`) for every colour.
- **Do** read a token at runtime with `cssColor('--token')` from `src/renderer/src/shared/lib/theme.ts` when a JS colour is required (three.js, canvas), and read it again when `useResolvedTheme()` changes.
- **Do** size controls and rows from `--density-*` so touch gets 44px targets for free.
- **Do** run `npm test` after changing a colour: `tokens.test.ts` fails on any contrast miss in either theme.
- **Do** keep the viewer, previews and swatches on `surface-viewer`.

### Don't:

- **Don't** write hex or `oklch()` literals, Tailwind palette colours (`zinc-*`, `amber-*`, `white/…`) or arbitrary `bg-[#…]` in components.
- **Don't** tint the chrome around the build or use the accent as a background wash.
- **Don't** signal state by colour alone.
- **Don't** animate layout, bounce or spring, or travel more than 4px.
- **Don't** import Electron in the renderer; theme and settings go through the preload API.

## Accessibility

WCAG 2.2 AA in both themes: 4.5:1 for text (including state, diff, lint and axis colours on every surface they sit on) and 3:1 for UI parts, input borders and the focus ring; `tokens.test.ts` checks every pair. Focus is always visible (2px `focus-ring`, 2px offset). Targets are at least 24px with a mouse (met by 36px controls) and 44px on coarse pointers. Icon buttons carry a label and a tooltip. States differ by icon or text as well as colour. Reduced motion is honoured as described under Motion. Modal layers (Dialog, Alert dialog, Sheet, Drawer, the Shortcuts list) are `aria-modal`: app shortcuts stay out of them except those marked for modals (Ctrl+K), one Esc closes them, and on close focus goes back to what had it, whether a trigger, a key, a menu or a store opened the layer (`useModalFocus`).
